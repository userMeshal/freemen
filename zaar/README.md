# زار — قل فكرتك، ومتجرك جاهز في ثوانٍ

منصة تجارة إلكترونية سعودية متعددة المتاجر. التاجر يكتب فكرته في محادثة، والذكاء الاصطناعي يبني له متجرًا كاملًا (اسم، هوية، تصميم، تصنيفات، منتجات بأسعارها)، ثم ينشره بخطوة واحدة. المنصة تتكفّل بالدفع، وتحوّل أرباح التاجر يوميًا، وتضمن كل طلب لعميله باسترداد كامل.

> المشروع يعيش في مجلد `zaar/` ولا يمسّ أي مشروع آخر في المستودع. التغيير الوحيد خارجه: إضافة `"zaar"` إلى `exclude` في `tsconfig.json` الجذر حتى لا يدخل ملفاته في بناء «حطّها».
> عند النشر على Vercel اضبط **Root Directory = `zaar`**.

## ما الذي يحتويه

| الجزء | التفاصيل |
| --- | --- |
| **الصفحة الرئيسية** `/` | كلمة «زار» العملاقة تحيطها شخابيط ترسم نفسها وتهتز (تقنية شعار «حطّها»)، شاشة افتتاح بعدّاد وستارة (PUFF)، بيان تمتلئ كلماته بالتمرير، مشهد تبادل «الفكرة ↔ المتجر»، رحلة أفقية مثبّتة من أربع خطوات، وحروف عملاقة تصعد في التذييل |
| **البناء بالمحادثة** `/start` | محادثة على جهة ومعاينة حية على الأخرى. أثناء البناء تظهر لوحة «يتكوّن الآن» تمتلئ بالاسم والمنتجات مع وصولها من البث. التعديل بالكلام («خل الألوان ذهبي»، «ارفع الأسعار 10%») |
| **الثيمات** | **جريء** ← تصميم PUFF SAUDI (كلمة عملاقة، تثبيت سينمائي، رحلة أفقية بين التصنيفات، ستارة انتقال، مؤشر مخصص). **ناعم** ← تصميم «حطّها» (كبسولة زجاجية عائمة، هالات، شخابيط، بطاقات متبادلة، وضع داكن). 10 لوحات ألوان |
| **واجهة المتجر** `/s/[slug]` | الرئيسية، كل المنتجات (بحث/تصنيف/ترتيب)، صفحة المنتج (خيارات، تقييمات، منتجات مشابهة)، سلة جانبية، إتمام الطلب، تتبع الطلب بدون حساب، صفحات السياسات |
| **الدفع** | EdfaPay (مدى/فيزا/ماستركارد/Apple Pay) + تابي + تمارا، مع بوابة تجريبية داخلية للاختبار |
| **ضمان زار** | العميل يطلب استرداد كامل من صفحة طلبه ← التاجر يوافق أو يعترض خلال مهلة ← إن لم يرد يُعتمد تلقائيًا ← إن اعترض تحسم إدارة زار |
| **المحفظة والتحويل اليومي** | دفتر أستاذ لكل متجر (مبيعة، عمولة، استرداد، إرجاع عمولة)، وتسوية يومية تنشئ تحويلًا واحدًا لكل متجر إلى الآيبان |
| **لوحة التاجر** `/dashboard` | الرئيسية (مبيعات، قمع التحويل، رسم 30 يومًا)، الطلبات والفواتير، المنتجات والتصنيفات والصور، الكوبونات، العملاء، السلال المتروكة (تذكير واتساب)، التقييمات، ضمان زار، المحفظة، التصميم بمعاينة حية، **مساعد زار**، الإعدادات |
| **لوحة الإدارة** `/hq` | نظرة عامة، المتاجر (إيقاف/تفعيل)، التحويلات اليومية (تأكيد/فشل/تصدير CSV)، طلبات الضمان، كل الطلبات، إعدادات المنصة (العمولة، مدة الضمان، مهلة الرد، حجز التحويل) |
| **التسويق و SEO** | بكسلات ميتا/تيك توك/سناب بأحداث الشراء، Metadata و JSON-LD لكل متجر ومنتج، نطاق فرعي لكل متجر (اختياري) |

## التشغيل محليًا

```bash
cd zaar
npm install
cp .env.example .env.local     # ثم عبّئ DATABASE_URL و AUTH_SECRET على الأقل
npm run db:setup               # ينشئ الجداول + متجرين تجريبيين (جريء وناعم)
npm run dev                    # http://localhost:3000
```

- المتجران التجريبيان: `/s/demo-street` و `/s/demo-oud` — دخول تاجرهما: `0500000001` / `zaar-demo-2026`.
- لوحة الإدارة: `/hq` ببيانات `ZAAR_ADMIN_EMAIL` / `ZAAR_ADMIN_PASSWORD`.
- خارج الإنتاج تعمل بوابة الدفع التجريبية تلقائيًا، فتقدر تجرّب الدورة كاملة بدون أي مفاتيح.

## متغيرات البيئة

القائمة الكاملة مع الشرح في `.env.example`. الأساسي:

| المتغير | الوصف |
| --- | --- |
| `DATABASE_URL` | PostgreSQL (Neon / Supabase / Vercel Postgres — رابط الـ pooled) |
| `AUTH_SECRET` | 32 حرفًا عشوائيًا على الأقل |
| `NEXT_PUBLIC_SITE_URL` | رابط المنصة النهائي |
| `NEXT_PUBLIC_ROOT_DOMAIN` | (اختياري) مثل `zaar.sa` لتفعيل `متجر.zaar.sa` — يحتاج wildcard domain في Vercel |
| `ZAAR_ADMIN_EMAIL` / `ZAAR_ADMIN_PASSWORD` | دخول لوحة الإدارة (كلمة المرور 12 حرفًا على الأقل) |
| `ANTHROPIC_API_KEY` | يفعّل Claude للبناء والمساعد. بدونه تعمل المنصة بالمولّد المحلي |
| `EDFAPAY_*` / `TABBY_*` / `TAMARA_*` | مفاتيح بوابات الدفع |
| `ZAAR_TEST_PAYMENTS` | `1` يفعّل البوابة التجريبية. **اتركه `0` في الإنتاج** |
| `CRON_SECRET` | يحمي المهمة اليومية |
| `BLOB_READ_WRITE_TOKEN` | رفع صور المنتجات (Vercel Blob) |

## النشر على Vercel

1. **Add New → Project** واختر المستودع، ثم **Root Directory = `zaar`**.
2. أنشئ قاعدة بيانات (Storage → Neon) وأضف `DATABASE_URL` وبقية المتغيرات.
3. Deploy — أمر `vercel-build` يطبّق ترحيلات القاعدة تلقائيًا.
4. `vercel.json` يسجّل المهمة اليومية (`/api/cron/daily` الساعة 00:05 بتوقيت الرياض)، و Vercel يرسل `CRON_SECRET` تلقائيًا.
5. لرفع الصور: Storage → Blob → Connect.

## كيف يعمل المال

زار هي التاجر المسجّل لدى بوابات الدفع: العميل يدفع لزار، وزار تحوّل للتاجر.

1. **عند الدفع** يُسجَّل في دفتر الأستاذ: `+ إجمالي الطلب` و `− عمولة زار` (الافتراضي 2.5% + 1 ر.س، تُعدَّل من `/hq/settings`).
2. **كل يوم** تجمع المهمة اليومية كل حركات المتجر غير المرحّلة حتى نهاية الأمس في تحويل واحد إلى آيبانه (إن بلغ الحد الأدنى).
3. **التحويل البنكي نفسه ينفّذه فريق المالية** من حساب الشركة (ملف CSV جاهز للتحويل الجماعي في `/hq/payouts`)، ثم يُؤكَّد في اللوحة بمرجع البنك. ربطه آليًا ببنك أو مزوّد مدفوعات خطوة لاحقة.
4. **عند الاسترداد** يُخصم كامل المبلغ من رصيد التاجر وتُعاد له العمولة. إن كان رصيده أقل يصير سالبًا ويُخصم من مبيعاته القادمة.

> **قرار تجاري يخصّك:** التحويل اليومي مع ضمان الاسترداد يعني أن زار قد تكون حوّلت مبلغًا ثم استُرد. إعداد «حجز التحويل» في `/hq/settings` (الافتراضي 0 = اليوم التالي) يؤخّر دخول المبيعة في التحويل بعدد الأيام الذي تحدده لتقليل هذا التعرّض.

## الذكاء الاصطناعي

- **بناء المتجر** (`src/lib/ai/claude.ts`): طلب واحد ببثّ مباشر ومخرجات منظّمة (structured outputs) وفق `BlueprintSchema`. كل مخرجات النموذج تمر على `normalizeBlueprint` قبل الحفظ. النموذج الافتراضي `claude-opus-5-5` بجهد `low` ويُغيَّر بـ `ZAAR_AI_MODEL`.
- **مساعد زار** (`src/lib/ai/assistant.ts`): حلقة أدوات (tool runner) بسبع أدوات مقيّدة بمتجر التاجر من الجلسة: تقرير المبيعات، قائمة المنتجات، إضافة/تعديل منتج، كوبون، تعديل التصميم، آخر الطلبات. لا أداة تحذف أو تمسّ الأموال.
- **المولّد المحلي** (`src/lib/ai/local.ts`): 14 مجالًا جاهزًا بمنتجاتها وأسعارها، يعمل بدون أي مفتاح، ويُستخدم تلقائيًا إن تعذّر الاتصال بـ Claude.

## ما تم اختباره وما لم يُختبر

**مُختبر هنا** (`node tests/e2e.cjs` والخادم يعمل على المنفذ 3100، يحتاج Playwright) — 42 فحصًا تمر كلها:
بناء متجر بالمحادثة وتعديله، إخفاء المسودة عن غير صاحبها، التسجيل والنشر، حفظ الآيبان، طلب ودفع، تجهيز، تسجيل المبيعة والعمولة، طلب استرداد من العميل وموافقة التاجر وخصمه من المحفظة، طلب ثانٍ، دخول الإدارة وصفحاتها، حماية المهمة اليومية، كل صفحات لوحة التاجر، مساعد زار، وعزل المتاجر. واختُبرت التسوية اليومية يدويًا (ومنها عدم التكرار عند تشغيلها مرتين)، وبناء الإنتاج `next build`.

**لم يُختبر مقابل الخدمة الحقيقية** — راجعه قبل التشغيل الفعلي:

- **Claude:** اختُبر مسارا البناء والمساعد مقابل خادم وهمي يحاكي واجهة Anthropic (البث، المخرجات المنظّمة، تنفيذ الأدوات)، لا مقابل الواجهة الحقيقية لعدم توفر مفتاح. جرّبه بمفتاحك وراجع جودة المتاجر الناتجة.
- **تابي وتمارا:** كُتب التكاملان وفق التوثيق العلني ولم يُجرَّبا على حساب حقيقي. جرّبهما في بيئة الاختبار لدى كل منهما (إنشاء الجلسة، العودة، الإشعارات، الاسترداد).
- **EdfaPay:** منقول من متجر PUFF. الاسترداد عبره يدوي حاليًا: تنفّذه من لوحة EdfaPay ثم تؤكده في `/hq/claims`.
- **النطاقات الفرعية ورفع الصور:** يحتاجان إعدادات Vercel (wildcard domain و Blob).
