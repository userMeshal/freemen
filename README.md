# حطّها — سوق المقايضة السعودي

موقع مقايضة بدون مال: تعرض غرضك، تحدد وش تبي بداله (أو تستقبل كل العروض)، يوصلك عروض بدل، تقبل اللي يعجبك وتتبادلون.

## الصفحات
- `/` الرئيسية — مشهد البدل المتحرك، كيف يشتغل، العروض، المميزات
- `/browse` السوق — بدل / بيع / مزاد، بحث، أقسام، مدن
- `/chat/[id]` محادثة بين صاحب إعلان ومهتم به
- `/admin` الإدارة — تفعيل طلبات دخول المزادات
- `/listing/[id]` صفحة العرض — التفاصيل، «اعرض بدلك»، ميزان البدل
- `/new` أضف عرض — ثلاث خطوات مع رفع صور
- `/offers` عروضي — وصلتني / أرسلتها / المفضلة

## التشغيل
```bash
npm install
npm run dev      # http://localhost:3000
```

## النشر
اربط المستودع بـ Vercel واضغط Deploy — ما يحتاج أي إعدادات.

## ثلاث طرق للعرض
- **بدل:** غرض بغرض، مع مبلغ اختياري يعدّل الفرق.
- **بيع:** سعر ثابت، والمشتري يرسل طلب شراء بالسعر أو بسعر يقترحه، وصاحب العرض يقبل أو يرفض.
- **مزاد:** سعر بداية وأقل زيادة ومدة. أعلى مزايدة عند انتهاء الوقت تفوز، والمزايدة في آخر دقيقتين تمدد المزاد دقيقتين.

### التعهد بسداد رسوم الموقع
عند الضغط على زر النشر تظهر نافذة التعهد (`components/PledgeModal.tsx`)، ولا يُنشر الإعلان إلا بعد الموافقة. الرسم 20 ريالاً عن كل عملية بيع مكتملة، ولا يُحصَّل شيء عند النشر — هذا تعهّد فقط وليس بوابة دفع.

- رقم نسخة التعهد يُرسل مع طلب النشر نفسه، والقاعدة ترفض أي إعلان بدونه (حتى بطلب API مباشر).
- عند النشر تُسجَّل الموافقة في جدول `pledges`: المستخدم، الإعلان، الوقت من ساعة الخادم، ونسخة النص. السجل لا يُعدَّل ولا يُحذف، ويبقى لو انحذف الإعلان.
- النص المعتمد في جدول `pledge_versions` ونسخة العرض في `lib/pledge.ts`، ولازم يتطابقان. تعديل النص = نسخة جديدة (`v2`) في المكانين.

### المحادثات
أي مستخدم مسجّل يراسل صاحب أي إعلان ظاهر من زر «راسل صاحب الإعلان»، دون انتظار قبول عرض. المحادثة = إعلان + الطرف المهتم، وعنوانها `/chat/l-<معرّف الإعلان>_<معرّف الطرف المهتم>`، وكل المحادثات تظهر في تبويب «الرسائل» بصفحة عروضي.

قواعد القاعدة: القراءة والكتابة لطرفي المحادثة فقط (حتى المشرف لا يقرأها)، الرسالة لا تُعدَّل ولا تُحذف، وصاحب الإعلان لا يبدأ مراسلة مستخدم لم يراسله أو يقدّم عرضاً أو يتصدّر مزاده. رقم الواتساب يبقى محجوباً حتى قبول عرض. الصفحة المفتوحة تتحدث كل 4 ثوانٍ، والتنبيه بالرسائل الجديدة كل 30 ثانية.

### رسوم المزاد ومراحله
القيم في `lib/site.ts`، والتطبيق الفعلي للمدد في `supabase/schema.sql`.

1. صاحب المزاد ينشره، فيُحفظ ولا يظهر للناس، ثم يحوّل **رسم العرض** (19 ريال) ويرسل بيانات التحويل.
2. المشرف يؤكد الدفع من `/admin`، فيبدأ المزاد **بعد 30 دقيقة** من التأكيد ويظهر للناس.
3. خلال هذه المدة يسجّل المزايدون: يحوّلون **رسم الدخول** (5 ريال) ويرسلون بياناتهم. التسجيل يقفل **قبل البداية بـ 5 دقائق**.
4. المشرف يفعّل المسجّلين، ومع بداية المزاد تفتح المزايدة للمفعّلين فقط.

قبل التشغيل:
1. عبّ `bank` في `lib/site.ts` (اسم صاحب الحساب، البنك، IBAN) — بدونه يتعطل طلب الدخول.
2. عيّن نفسك مشرفاً من SQL Editor:
   ```sql
   insert into public.admins select id from auth.users where email = 'بريد-حسابك-في-الموقع';
   ```

المنصة لا تستلم ثمن الأغراض؛ الدفع بين الطرفين عند التسليم. المبلغ الوحيد الذي يدخل حساب المنصة هو رسم المزاد.

## عروض البدل والمبلغ
عرض البدل = غرض بقيمة تقريبية بالريال + مبلغ اختياري يعدّل الفرق. «ميزان البدل» يقارن قيمة الغرض المعروض بقيمة عرض البدل كاملة (الغرض + المبلغ). صاحب الغرض يقبل أو يرفض، والمبلغ ما يتعدّل بعد الإرسال.

> عند تحديث نسخة قديمة: شغّل `supabase/schema.sql` من جديد في SQL Editor **قبل** نشر الكود (يضيف أعمدة القيمة والمبلغ).

## قاعدة البيانات وتسجيل الدخول (Supabase)
الموقع له وضعين:
- **تجريبي** (الافتراضي): بدون إعداد، البيانات في متصفح الزائر مع عروض نموذجية.
- **حقيقي**: أول ما تنضبط قيم Supabase — حسابات بإيميل وكلمة مرور، عروض يشوفها الكل، صور مرفوعة، وعروض بدل توصل لحظياً.

### التفعيل
1. أنشئ مشروع في [supabase.com](https://supabase.com).
2. **SQL Editor** ← الصق محتوى `supabase/schema.sql` كامل ← **Run**.
3. **Authentication ← Sign In / Providers ← Email** ← اطفئ **Confirm email** (إيميلات Supabase المجانية محدودة جداً بالساعة).
4. من زر **Connect** انسخ `Project URL` والمفتاح العلني (`publishable` أو `anon`). لا تستخدم `service_role` أبداً.
5. حط القيمتين في `.env.production` باسم `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (علنيتين، وهي مضبوطة حالياً على مشروع «حطّها»)، أو أضفهم في Vercel ← **Environment Variables**.

للتشغيل المحلي: انسخ `.env.example` إلى `.env.local` وعبّ القيم.

### استرجاع كلمة المرور
من صفحة الدخول ← «نسيت كلمة المرور؟» ينرسل رابط على الإيميل يفتح `/reset`. عشان الرابط يرجّع المستخدم للموقع الصحيح، اضبط في Supabase ← **Authentication ← URL Configuration**:
- **Site URL**: رابط الموقع (مثل `https://suysaudi.co`).
- **Redirect URLs**: أضف `https://suysaudi.co/**` وأي رابط ثاني للموقع (مثل رابط Vercel).

إيميلات Supabase المجانية محدودة بعدد قليل بالساعة؛ للاستخدام الفعلي اربط مزوّد بريد (SMTP) من **Authentication ← Emails ← SMTP Settings**.

### الأمان
كل القواعد في القاعدة نفسها (RLS) داخل `supabase/schema.sql`:
- العروض يقرأها الكل، وما يعدّلها أو يحذفها إلا صاحبها.
- عرض البدل يشوفه مرسله وصاحب الغرض فقط، والقبول/الرفض لصاحب الغرض فقط.
- رقم الواتساب في جدول مستقل ما ينقرأ إلا بين طرفين بينهم عرض مقبول.
- كل مستخدم يرفع الصور داخل مجلده فقط.

### غير موجود للحين
تعديل العرض بعد نشره، والتبليغ عن عرض مخالف.

## السياسات
خمس صفحات تحت `/policies`: الشروط والأحكام، الخصوصية، الإلغاء والاسترجاع، الحماية والأمان، والأغراض الممنوعة. النصوص في `lib/policies.ts` وبيانات الموقع (الاسم، بريد التواصل، الجهة المشغّلة) في `lib/site.ts`.

النصوص مسودة تصف طريقة عمل الموقع الحالية، وتحتاج مراجعة مختص قبل الاعتماد عليها. أي ميزة تمسّ المال أو البيانات لازم تنعكس عليها قبل الإطلاق.

## الشعار
الشعار كلمة «حطّها» مرسومة، ومحوّلة من الملف الأصلي إلى مسار متجهي واحد. ملفاته في `public/brand/` (وتنفتح من الموقع على `/brand/اسم-الملف`):

| الملف | الاستخدام |
| :--- | :--- |
| `logo` | الشعار بلونه الكحلي `#111226` على خلفية فاتحة |
| `logo-white` | الشعار بالأبيض للخلفيات الداكنة |
| `icon` / `icon-white` | أيقونة مربعة — حسابات التواصل وأيقونة التطبيق |

كل ملف بصيغة SVG (يتكبّر لأي حجم) و PNG بخلفية شفافة. داخل الموقع يُرسم الشعار من `lib/logo.ts` ويأخذ لون النص، فيتبع الوضع الفاتح والداكن.
في واجهة الرئيسية يظهر الشعار بحركة (`components/HeroLogo.tsx`): ينكشف من اليمين ثم ترتسم حوله شخابيط تهتز كأنها مرسومة باليد، والضغط عليه يعيد الحركة.
